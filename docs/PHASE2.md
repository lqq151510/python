# 第二阶段：文档知识库与可追踪的检索

本轮继续采用本地与模拟验收；真实 DeepSeek 与向量语义检索分别留待后续验证。

## 范围与实施顺序

1. 复用模板认证、PostgreSQL 与组件，新增按用户隔离的文档和分块表。
2. 导入 UTF-8 Markdown/TXT：限制文件大小、校验文本、按标题和字符窗口分块，保留来源行号；同一用户重复内容不重复存储。
3. 实现小型语料库的 BM25 关键词检索，返回片段、文档名、标题、行号和得分；不把该算法描述成向量语义检索。
4. 增加知识库页面，完成上传、列表、检索、删除与空结果/错误提示；聊天可选择检索文档，将来源作为不可信参考材料传给模型。
5. 验证数据库迁移、权限隔离、重复上传、输入限制、分块来源、排序、无命中和引用呈现；保留第一阶段回归测试。
6. 给出可复现的演示文档、小型检索评估及学习练习。

## 验收标准

- 页面上传一份示例 Markdown，刷新后仍能看到文档；重复上传不增加重复记录。
- 检索能命中预期片段，来源文件名和行号可以核对；无匹配时给出明确提示。
- 用户不能检索、读取或删除他人的文档，包括管理员也只能访问自己的知识库。
- 删除文档与其分块在同一事务完成；接口与页面异常状态一致。
- 普通问答仍保持第一阶段行为；文档模式无证据时停止，模拟模型回答能呈现本次检索来源。
- 所有真实模型调用保持暂缓，不把模拟生成结果作为真实 DeepSeek 成果。

## 当前选择的边界

单文件最多 256 KiB、最多 120000 个字符，每位用户最多 20 份文档；小型语料库在后端计算 BM25 排序，按用户过滤后才读取片段。阻塞数据库与文本处理放在线程池执行，不直接占用异步模型接口的事件循环。不增加 Chroma、Milvus 或编排框架。

原始上传文件不会另存到本地路径，文本和片段保存在本项目数据库。Markdown 按纯文本展示，文档内的命令不会执行。引用列表表示本次检索得到的来源，不等同于模型回答每句话都已验证。

## 接口与数据流

上传：浏览器选择文件 → Bearer 鉴权 → 请求体大小保护 → UTF-8 解码和校验 → 标题/窗口分块 → 同内容去重 → 同一事务保存文档与片段。

检索：问题 → 先按用户筛选数据库记录 → 英文词与中文双字片段分词 → BM25 评分 → 最多 5 个片段 → 展示引用编号、文件名、标题和来源行号。评分考虑词频、常见程度与片段长度，当前为小语料库的内存排序基线。

文档问答：选择 `use_documents` → 在线程池中检索 → 无匹配时返回 422 → 有匹配时把只读资料与问题交给异步模型适配 → 返回答案和本次检索来源。普通问答保留原来的请求和响应。真实模型密钥为空时，有匹配仍返回 503，不会用模拟答案代替真实调用。

数据库新增 `document` 与 `documentchunk`，外键级联删除；索引支持按用户和文档筛选，唯一约束保护同用户内容去重及分块序号。上传时锁定该用户的数据库行，保证并发请求也不能绕过数量上限。所有 SQL 错误隐藏绑定参数，避免把文档内容写入异常日志。

## 实际验收证据

- 后端 **115 项测试通过**，包含新增 24 项知识库、上传和并发测试以及第一阶段回归；独立临时数据库已移除。
- Chrome 模拟交互 **16 项测试通过**，包括第一阶段的 8 项和知识库/文档问答的 8 项；TypeScript、生产构建、Ruff、mypy 与 ty 均通过。
- 并发测试验证同内容两次导入只产生一个文档，也验证同一用户并发导入不能绕过数量上限。上传体限制同时覆盖有长度标头和无长度标头的请求。
- 真实浏览器上传 `async.md`、`operations.md`、`model-errors.md`，分别得到 3、3、4 个分块；刷新后仍可读取列表。
- 检索“读取超时是否重试”首先命中 `model-errors.md` 的第 16～20 行，并可以展开核对原文。
- 真实文档模式返回缺密钥 503，未命中时返回 422，均附请求标识；浏览器页面运行错误为空。
- 重启后再次上传三份示例均返回 200 与 `duplicate: true`，应用仍保留 1 个账号、3 份文档与 10 个分块；没有剩余临时测试数据库。真实超大上传返回 413，前端 42 个构建产物未检出本地现有凭据。
- 小型人工评估共 12 个样例：10 个有相关文档的问题、2 个无匹配问题。当前 Top-1 命中率、Recall@5（前五项召回率）与无命中判断均为 100%。这只说明随项目附带的简短样例符合预期，不代表真实项目文档质量或模型回答质量。
- Alembic 实际迁移成功，`alembic check` 确认模型与数据库结构一致。
- 本地证据：`.local/knowledge-smoke.json`、`.local/knowledge-runtime.json`、`.local/knowledge-live.png`、`.local/retrieval-eval.json`。这些文件不提交到 Git。

## 验证命令

从项目根目录启动 `bash scripts/devassist-dev.sh`。Docker Desktop 需运行；开发服务监听本地回环地址。

```bash
cd backend
uv run --frozen python scripts/test-local.py
uv run --frozen python scripts/evaluate-retrieval.py

cd ../frontend
bun run build
PLAYWRIGHT_BROWSER_CHANNEL=chrome PLAYWRIGHT_BASE_URL=http://localhost:5173 \
  bunx --no-install playwright test -c playwright.knowledge.config.ts
```

隔离脚本创建带随机后缀的临时数据库，将 `DATABASE_URL` 只传给测试子进程；测试结束或失败后移除该临时数据库。应用数据库不会执行模板测试的全表清理。

## 泽宝亲手完成的小练习

1. 上传自己写的 20 行 Markdown，包含两个标题。检查分块数量，检索其中一句话并核对来源行号。
2. 把一句话改成相近意思、不同用词，再检索。记录词面匹配漏掉哪些问题，解释为什么需要后续的 embedding（向量表示）。
3. 在 `examples/retrieval-eval.json` 的 `cases` 数组加入 3 个你自己的问题，先依据原文填写 `expected` 的文件名、行号和引用，再运行评估脚本。样例格式与当前片段级结果见 [评估说明](RETRIEVAL_EVAL.md)；保留失败问题用于分析。
4. 在 `backend/app/knowledge.py` 调整 `CHUNK_CHARACTERS` 与 `CHUNK_OVERLAP`，删除并重新导入示例文档，比较片段完整性与排序；最后恢复原值。重复上传只复用旧记录，不会自动重新分块。
5. 用两个账号导入不同文档，说明为什么权限必须在数据库查询层过滤，不能只在页面隐藏。

## 面试与下一步

当前可以据实描述：复用 FastAPI 全栈模板，实现认证、文档解析与分块、PostgreSQL 持久化、用户隔离、内容去重、BM25 检索、引用展示和隔离数据库回归测试。模型适配及文档问答协议已做模拟验证；真实模型回答、向量检索、Agent 和生产部署仍待验收。

下一步用更接近真实项目的文档与问题集评估检索，再决定向量模型及混合检索方案。随后配置本地模型密钥，单独检查引用是否支持回答。未来变更数据库大版本或回滚迁移前需要备份；该阶段迁移的 downgrade 会删除知识库表及文档，只应在确认范围或临时验证数据库中执行。

## 本轮复盘

- 先把文档的输入边界、来源行号和用户权限做实，再接入检索和模型，方便分别定位解析、召回与生成的问题。
- 原模板测试有全表清理行为；新增持久化数据后改用临时数据库，测试不再依赖清理开发数据。
- 上传和删除的加载状态覆盖列表刷新，避免请求已结束但页面列表尚未更新时再次提交。浏览器测试用受控延迟验证这一行为。
