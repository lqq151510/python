# 知识库回答的资料不足判断与引用校验

记录日期：2026-10-26，Asia/Shanghai。本轮承接 [排序与页面状态优化](RAG_OPTIMIZATION.md)，新增默认关闭的知识库生成实验分支；检索排序、数据库结构和前端响应字段保持兼容。真实小模型实验未通过启用条件，不能宣称无答案识别已有提升。

## 问题与实现

之前只要检索返回片段，模型的任意非空文字就会作为回答保存。系统提示虽要求资料不足时说明，但没有可检查的答案状态或原文引文。主题相关的片段未必包含问题要求的数值、配置或操作步骤。

`backend/app/grounded_answer.py` 提供纯函数构建提示和校验输出；`backend/app/chat.py` 仅在显式开启 `CHAT_VALIDATE_DOCUMENT_EVIDENCE=true` 且有文档来源时请求 JSON 模式。该配置默认 `false`，现有 `.env` 未被改动。开启后同一次模型请求返回如下结构，应用校验后仍向浏览器返回原有字符串 `answer`：

```json
{
  "answerable": true,
  "answer": "排队中的任务可以取消，执行中的任务不能取消。[S1]",
  "evidence": [
    {"citation": 1, "quote": "排队中的任务可以取消；已经开始执行的任务不接受取消。"}
  ]
}
```

- 可以回答：字段和类型必须符合严格结构；答案非空，至少有一条引文；编号属于当前检索来源，引文必须逐字存在于对应正文；答案的来源标记须经过引文校验。
- 资料不足：模型明确返回 `answerable=false` 时，应用丢弃其自填正文，统一展示“当前参考资料不足以回答这个问题。请补充相关文档或调整问题后重试。”
- 模型响应错误：非法 JSON、多余字段、错误类型、伪造来源、非原文引文、缺少引用或截断输出仍返回 `502/model_invalid_response`，不计作正确拒答，也不写历史。
- 没有检索片段：沿用 `422/no_document_evidence`，不调用模型、不写历史。

默认知识库聊天保留原提示词与文本协议；普通聊天即使开关开启也继续接收文本，不发送 JSON 模式参数。总请求预算、原有有限网络重试和模型输出上限保持原约束，没有增加一次判定或格式修复请求。请求格式参考 [DeepSeek JSON Output 官方说明](https://api-docs.deepseek.com/guides/json_mode/)；支持该参数不代表供应商必定按应用的字段结构输出，服务端校验仍是必要步骤。

**原文存在性校验不能证明语义充分性。** 模型仍可能引用真实但不支持其结论的句子，因此回答正确与否须独立评估；本实现不声称消除幻觉。

## 历史与接口边界

实验模式的明确拒答是正常的 `200` 回答，继续保存本次检索片段，供用户核对资料；片段仍表示“本次检索片段”，并非每条都被回答采用。相同请求的幂等重放返回原先保存的文本，不再调用模型。

已有历史回答不会自动重新校验；旧请求键仍重放其原答案。未新增只在首次响应存在、历史却无法保存的答案状态字段，也没有数据库迁移或新增依赖。

## 冻结的真实模型小样本实验

新增 `examples/answerability-eval.json`：三份独立原创且明确标注虚构的技术说明，共 12 题，有答案与资料不足各 6 题。标注作者未读取应用实现、旧检索题目或模型结果；生成实现代理未读取新题集。文件于首次实验前冻结，SHA-256 为：

```text
0bb476887de9aecb38fba287f5895028a11c3894f5958daaeeef40991c0e3d65
```

实验直接提供每题指定文档全文作为一个 `S1` 来源，比较冻结的旧提示与当前结构化候选。它检验给定上下文下的生成与拒答，不检验检索排序、分块或全库找资料的能力。

事先验收条件：有答案题的正常回答数不低于基线；无答案题的正确拒答数高于基线；协议或请求错误不得计入正确拒答；最终逐题人工核对答案是否受资料支持。候选在首次新题评估前固定，不根据这组题的结果继续调参。

本机已有 `qwen2.5-1.5b-instruct:latest` 在 2026-10-26 完成配对实验：24 次真实调用，每题每模式各一次，无重试，约 36.2 秒；没有请求异常。人工复核独立核对每题问题、原文和原始答案，不把拒答关键词或非空文本直接计为语义正确。

| 指标 | 旧文本提示 | 严格候选 |
|---|---:|---:|
| 有答案题正确／正常回答 | 人工语义正确 5/6 | 应用校验接受 0/6 |
| 无答案题正确说明资料不足 | 人工语义正确 2/6 | 明确拒答 0/6 |
| 应用协议错误 | 0/12（旧协议仅要求非空文本） | 12/12 |
| 请求错误 | 0/12 | 0/12 |
| 引文来源校验通过 | 未检查 | 5/12 |
| 单次调用平均耗时 | 0.863 秒 | 2.142 秒 |

两列的“语义正确”和“应用校验接受”是不同口径，不能直接当作模型准确率对比；候选没有一个可展示答案，已足以判定不满足预设条件。

严格候选 12 条均是合法 JSON、正常结束，10 条满足字段结构；按首次拒绝位置分为：缺少 `evidence` 2 条、非逐字原文引文 5 条、正文缺少来源标记 5 条。实际 12 条正文均无来源标记，并全部声明 `answerable=true`，包含全部 6 道资料不足题。引文真实也未阻止编造：部分答案将超时秒数当成图片大小，或自行给出资料没有的缓存份数。

旧路径的正例失败为 `sensor_02`：把缺少必填字段错当成重复记录判定，遗漏“同设备＋同采集时间”；负例中只有 `sensor_03` 和 `cache_03` 明确说明未知，其余四题编造图片大小、进程总数、报告保留天数或缓存份数。`image_01` 和 `cache_03` 的措辞另有瑕疵，人工判定保留了备注。

完整逐题原始输出、标注原文、应用错误和独立人工复核见 [实验记录](ANSWERABILITY_EVAL_REPORT.md)。真实结果证明当前小模型的候选协议遵循与拒答能力未达标；不据此断言其他模型同样失败，也不把候选拒绝了错误输出等同于可以正常回答。

**启用结论：默认关闭实验模式。** 候选提示词、校验器和资料均未根据这些结果调整；后续仅增加默认关闭的配置开关，保护原有可用路径。本题集今后作为回归集使用，新的模型资格结论应再使用未参与调试的独立样例。

## 复现与证据

从 `backend/` 运行，不需要项目 `.env`、数据库或云端密钥；本机应已运行 Ollama 并安装指定模型。脚本不自动下载模型，只允许回环地址，不跟随重定向，不读取代理环境：

```bash
PYTHONPATH=. ../.venv/bin/python scripts/evaluate-answerability.py \
  --mode both \
  --model qwen2.5-1.5b-instruct:latest \
  --json-output ../.local/answerability-eval/reproduced.json \
  --report ../.local/answerability-eval/reproduced.md
```

双方使用相同模型、指定文档和生成参数；每题每种模式最多一次调用，无评判模型。报告分别保存提示词、数据和代码指纹、原始合成资料实验输出、最终文本、协议结果、调用次数与延迟。基线的关键词拒答标记只供人工筛选，不能直接作为准确率。

离线测试、数据库回归和真实实验是不同证据层次。原有运行检查中的“回答非空且来源正确”只能证明链路成功，不能证明该回答包含问题所需事实；本轮实验须额外检查正例事实与负例是否编造。
