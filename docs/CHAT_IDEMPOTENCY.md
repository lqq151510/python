# Chat 请求去重与恢复边界

默认 `CHAT_IDEMPOTENCY_CLAIMS_ENABLED=false`，不会访问新增表，但旧行为仍可能并发重复调用模型。仅在隔离数据库应用并验证迁移后设置 `CHAT_IDEMPOTENCY_CLAIMS_ENABLED=true`。开启后，提交 `client_request_id` 时，系统先用短事务按用户和请求编号建立持久认领，再调用模型；模型调用期间不保持数据库事务。成功时，回答和认领完成状态在同一个事务中提交。没有提供编号的旧调用保持原有行为。

工作台和聊天页均会为请求传递 `client_request_id`，并在用户重试原请求时复用编号。工作台的请求快照仅保存在页面内存，刷新后不保留；其他调用方也必须为同一逻辑请求传递并复用编号。

相同编号与不同请求内容返回 `409 idempotency_key_reused`。相同编号的任务仍在处理时返回 `409 request_in_progress`，可以稍后使用相同编号获取已完成结果。调用模型前失败返回 `409 request_failed`；发生中断、调用后异常或任务超过三分钟仍未完成时返回 `409 request_outcome_unknown`。确认可能的重复费用后，用户可以使用新编号发起新的请求；服务不会自动重新调用模型，因为上游可能已经处理过原请求。

需要先应用 Alembic 迁移 `df42e8a190cb` 才能启用该代码。旧的成功问答记录仍通过原来的请求编号和摘要查询；认领记录不包含问题正文或答案，随账号删除级联删除。当前没有认领记录的定期清理；实现清理时不得删除仍需用于去重的记录。
