# 知识库回答的来源编号检查

普通知识库问答仍使用一次文本生成；旧的严格 JSON 证据实验保持原有开关与行为。
模型返回内容后，服务端检查正文的来源编号是否属于本次检索的来源，并检查每个非空段落和列表项是否包含编号。常见的中性标题可不带编号；围栏代码块须在结束标记后紧邻来源编号，代码内部的字符串不计为来源。`[status]`、`[start]` 等普通技术术语不视为来源编号。

如果生成被截断、缺少编号、存在不存在或明显格式错误的编号，服务不会为模型结论自行补贴来源，而是返回**明确标识为原文摘录的降级内容**，至多取前三条来源、每条前 300 字；原有来源面板继续返回完整检索片段。模型明确返回系统的固定“资料不足”答案时保留该拒答，不强制添加编号。

编号检查只说明编号存在和格式覆盖，**不能证明来源支持模型的结论，也不能证明资料充分或回答正确**。需要结合原文核对，并用正题、无答案和诱导题评估。代码块格式、复杂表格或使用其他标号约定的回答可能因保守校验而退回原文摘录；可用来源面板查看原文。

数字方括号紧邻英文标识符时按数组下标处理，例如 `items[0]`；独立的 `[9]` 按可疑来源处理。此规则无法完全识别任意伪造标注，例如与英文单词紧贴的 `[9]` 可能被当作下标，建议模型使用反引号包裹代码并人工核对来源。

当前不会为了补编号额外调用模型，所有原有超时、有限重试和错误路径保持不变。输入文档及其摘录始终是不可执行的数据，不被赋予系统指令权限。
