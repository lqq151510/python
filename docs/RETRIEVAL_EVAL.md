# 片段级检索评估使用说明

> 本文保留 2026-10-11 的评估实现与历史结果，包括 20/30 和 139 项后端测试；这些数字不代表当前版本。最新 2026-10-23 的参数对照、24 题独立留出集、262 项后端回归和复现命令见 [本轮优化记录](RAG_OPTIMIZATION.md)，留出集完整结果见 [留出集报告](RETRIEVAL_HOLDOUT_REPORT.md)。下文“本轮”“此次”均指 2026-10-11 的历史工作。

本文记录的历史完成日期：2026-10-11，Asia/Shanghai。

## 数据与实现

数据集版本为 2，包含 30 个问题：直接提问 8 个、不同表述 6 个、无答案 6 个、长文 5 个、指定文档 5 个。指定文档类别另含 2 个无答案问题，因此总共有 22 个有答案问题、8 个无答案问题。

语料共 5 份、17 个分块：保留原来的 3 份知识库示例，另加入合成的服务说明与超过分块长度的排障演练手册。长文在相同标题下产生多个分块，用来检验错段、重叠和多条证据召回。这些文件没有导入应用数据库，也不包含个人资料或真实凭据。

标注在运行新评估之前依据原文编写。此次没有根据检索结果改动标注，也没有调整 BM25 的分词、排序、分块参数或增加向量模型。

- `backend/app/retrieval_eval.py`：标注验证、语料加载、片段匹配、评分、分类统计与 Markdown 报告生成。
- `backend/scripts/evaluate-retrieval.py`：命令行入口、JSON/Markdown 输出与退出码。
- `backend/tests/test_retrieval_eval.py`：评分、范围、标注验证和离线运行测试。
- `backend/app/knowledge.py`：数据库引擎改为在实际数据库检索函数内导入，使纯解析、分块、排序与评估无需加载 `.env` 或数据库配置；在线接口行为不变。

## 使用与退出码

从项目的 `backend/` 目录运行：

```bash
uv run --frozen python scripts/evaluate-retrieval.py
```

默认产物是 `.local/retrieval-eval.json` 和 `docs/RETRIEVAL_EVAL_REPORT.md`。JSON 保存每个问题的标注证据、前五个完整返回片段、行号、分数和命中证据编号；Markdown 提供指标、类别对比、所有问题的标注位置与首条位置、失败原因和原文摘录。

可用 `--dataset` 指定另一个版本 2 数据集，用 `--json-output`、`--report` 指定输出路径。语料路径仍相对于项目 `examples/`，不能超出该目录，文件名必须唯一。

```bash
uv run --frozen python scripts/evaluate-retrieval.py --strict
```

| 退出码 | 含义 |
|---|---|
| 0 | 报告生成成功；默认诊断模式允许保留检索失败样例 |
| 1 | 开启 `--strict` 后，至少一个样例未满足严格检索要求；报告仍生成 |
| 2 | 标注或语料输入无效，例如引用不在原文行内、文件不存在、范围错误或重复标注 |

2026-10-11 的历史基线在 30 个问题中严格通过 20 个，`--strict` 返回 1 属于当时已知评估结果，不是代码回归失败。2026-10-23 的当前参数为 22/30，仍未满足全部严格通过条件；固定回归门槛与严格全通过是不同检查。

## 样例格式与评分

`examples/retrieval-eval.json` 顶层包含 `schema_version`、`dataset_id`、`description`、`corpus` 和 `cases`。一个问题的示例：

```json
{
  "id": "S02",
  "category": "scoped",
  "query": "Alembic 数据库迁移",
  "scope": "operations.md",
  "expected": [{
    "filename": "operations.md",
    "line_start": 6,
    "line_end": 6,
    "quote": "数据库结构通过 Alembic 迁移管理"
  }]
}
```

`scope: null` 表示搜索全部评估语料。`expected: []` 表示原文没有该问题需要的操作证据。多条必要证据分别标注在 `expected` 中，不把重叠片段重复标注为不同证据。

只有文件名相同、返回片段覆盖证据行号、原文包含标注引用三个条件都满足，才算召回该证据。这样能识别同一文件的错误片段，也能识别长行分割后只保留部分内容的情况。

Top-1 命中率和 MRR@5（首条正确证据排名倒数的平均值）只统计有答案问题。Recall@5 先计算每个有答案问题前五条召回的证据比例，再对问题取平均；这是按问题平均，不能与全体证据合并后的比例混用。没有对应类别时用 `null`/“不适用”，避免零分母。

无答案返回片段比例只衡量没有操作证据的问题是否仍返回片段。片段可能主题相关，也可能说明某项功能未实现；这不代表模型已生成错误答案。是否能根据这些片段正确说明资料不足，要在真实模型阶段另外评估。

严格通过要求有答案问题首条正确且前五条召回全部证据，无答案问题返回空结果。原文有标注但任何分块都没有完整保留引用时，会单独标记分块证据丢失，不能把标注改成“无答案”。

## 复盘与后续实验

旧版的 12 个文件名级样例较容易通过，新版暴露出不同表述漏检、相关关键词带来的无答案返回、长文排序和多证据漏召回。两个版本的语料、问题和评分口径不同，不能把新版数字当作旧版效果下降。

下一轮可以分别测试更完整的段落分块、不同表述的词汇覆盖与无答案判定。当前数据集已经用于诊断，针对它调参后应加入独立问题集复验，避免只改善已知样例。向量检索与模型回答需要单独记录依赖、成本和真实结果。

修改前副本位于 `.local/retrieval-eval-baseline/`。回滚时逐文件对比恢复脚本、标注、说明与 `knowledge.py` 的导入改动；新建评估模块、测试及合成语料在解除引用后可移除。没有数据库迁移，不需要回滚数据表。此次未提交、推送或发布。
