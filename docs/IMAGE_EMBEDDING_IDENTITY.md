# 图片向量空间身份与回滚边界

图片上传和搜索使用同一次本地 worker `/embed` 响应中的向量和模型空间身份；缺少合法身份的旧 worker 会返回明确错误，不会保存新图片向量。新图片的 `embedding_json` 使用 `{version: 1, space_id, vector}` 封套，无需更改数据库结构。

搜索时逐项比较已保存的 `space_id` 与当前查询的空间身份；即使两个向量维度相同，身份不同也不会进行相似度计算。历史 JSON 数组没有身份，不能猜测其来源，搜索会返回 `embedding_identity_unknown`。历史图片的列表、查看和删除不依赖该向量字段，保持可用；此更改不会批量修改、删除或重建现有图片和向量。

图片页面提供逐张主动执行的“重新生成检索向量”，仅处理当前账号所选图片；重复上传仍会根据内容摘要复用旧记录，不会重新生成向量。重建前使用有界读取核对原图大小、类型及 SHA-256，编码模型调用期间不保留数据库事务。完成后再次检查文件，并通过条件更新确认图片行及旧向量未被并发修改；模型失败、文件变化或并发删除时不会写入新向量。每次重建的新封套附随机 revision，避免应用内更新产生相同内容的 ABA 问题。对于不经过应用、直接修改磁盘的外部程序，文件校验与数据库写入无法构成跨文件系统的原子事务；应避免同时修改。

重建不会修改原图，且不会批量或自动执行；每次用户点击至多发出一次嵌入请求，不会自动重试。网络超时或数据库提交连接中断时结果可能未知，应先刷新、核对后再决定是否手动重试。存有重要图片时建议先备份。新封套版本为 `2`，旧版身份封套版本 `1` 继续可读。仍未执行任何现有用户图片的重建。

回滚到不认识封套的旧版代码后，新版保存的图片原文件、元数据仍在，但旧版图片检索无法解析封套。安全回退优先恢复兼容读取封套的新版本，或先备份并为旧版本提供经测试的只读兼容；不要直接剥离身份字段或批量转换来冒充模型一致性。无论何种回退，都不自动删除或重建数据。

离线测试使用 SQLite、临时图片目录和模拟 worker 响应，覆盖同维不同身份、旧格式、缺失/伪造身份、重复上传和原图保留；不连接应用数据库或加载真实模型。实际部署需先通过隔离联调确认新 worker 与后端协议一致，再取得相应服务操作授权。
